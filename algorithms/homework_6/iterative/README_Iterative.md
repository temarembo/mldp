# Iterative — mergesort и quicksort без рекурсии

## Условие

Реализовать итеративные версии mergesort и quicksort.

Код и тесты находятся в [Iterative.py](Iterative.py).
Обе функции возвращают новый список по возрастанию и сохраняют исходный массив.
В реализации нет рекурсивных вызовов, готовой сортировки или внешних библиотек.

Рекурсивные версии разобраны в [README задачи Compare](README.md).

## Запуск

Из корня проекта `study`:

```bash
python3 mldp/algorithms/homework_6/Iterative.py
```

Скрипт запускает тесты, выводит пример сортировки и сравнивает время
итеративных mergesort и quicksort на четырёх типах массивов.
Запускать нужно без `-O`, чтобы Python выполнял проверки `assert`.

Пример использования из папки `homework_6`:

```python
from Iterative import mergesort, quicksort

nums = [9, 3, 7, 1, 8, 2, 6]

assert mergesort(nums) == [1, 2, 3, 6, 7, 8, 9]
assert quicksort(nums) == [1, 2, 3, 6, 7, 8, 9]
assert nums == [9, 3, 7, 1, 8, 2, 6]
```

## Итеративный mergesort

В рекурсивной версии сначала делили список на половины, а затем при возврате
из вызовов сливали их. Здесь начинаем сразу со слияний, от маленьких участков
к большим. Такой подход называется bottom-up — снизу вверх.

Каждый отдельный элемент уже отсортирован. Поэтому можно:

1. Слить соседние участки длины `1` и получить отсортированные участки длины до `2`.
2. Слить соседние участки длины `2` и получить участки длины до `4`.
3. Затем сливать участки длины `4`, `8`, `16` и так далее.
4. Закончить, когда один отсортированный участок охватит весь список.

### Переменные и границы

- `width` — длина уже отсортированных участков перед проходом.
- `arr` — список, из которого читаем элементы на текущем проходе.
- `buffer` — список такой же длины, в который записываем результаты слияний.
- `start`, `middle`, `end` — границы двух соседних участков.
- `i` и `j` — указатели на очередные элементы левого и правого участков.
- `k` — позиция записи в `buffer`.

Буфер создаётся как `buffer = arr.copy()`, поэтому содержит элементы того же
типа, что и исходный список. Начальное содержимое не важно: каждый проход
полностью перезаписывает буфер. Заполнение через `[None] * n` тоже позволило бы
выполнить алгоритм, но после обмена `arr, buffer` анализатор типов может считать
элементы `arr` равными `None` и предупреждать о сравнении через `<=`.

Границы используются как в срезах Python: левая включается, правая исключается.

```text
           левый участок          правый участок
      [start ... middle - 1]  [middle ... end - 1]
               ↑                      ↑
               i                      j
```

`min(..., n)` обрезает границы по длине списка. Это нужно, когда длина массива
не является степенью двойки: последний участок может быть короче, а его
правый сосед может вообще отсутствовать.

После каждого прохода выполняется:

```python
arr, buffer = buffer, arr
width *= 2
```

Списки обмениваются ролями: готовый результат становится источником для
следующего прохода, а старый источник — местом записи. Обмен ссылок не копирует
элементы и занимает `O(1)`. Перед очередным обменом весь буфер перезаписывается,
поэтому его старое содержимое не влияет на результат.

### Визуализация на массиве нечётной длины

```text
Исходный массив:
[9, 3, 7, 1, 8, 2, 6]

width = 1:
[9] + [3]   [7] + [1]   [8] + [2]   [6] + []
    ↓           ↓           ↓           ↓
 [3, 9]      [1, 7]      [2, 8]        [6]

arr = [3, 9, 1, 7, 2, 8, 6]

width = 2:
[3, 9] + [1, 7]         [2, 8] + [6]
        ↓                      ↓
   [1, 3, 7, 9]            [2, 6, 8]

arr = [1, 3, 7, 9, 2, 6, 8]

width = 4:
[1, 3, 7, 9] + [2, 6, 8]
              ↓
    [1, 2, 3, 6, 7, 8, 9]

width = 8 >= 7 → сортировка закончена.
```

Последний элемент `6` не теряется: на первом проходе у него нет правого соседа,
поэтому цикл копирования остатка левой части переносит его в буфер.

### Почему алгоритм корректен

Перед первым проходом каждый участок длины `1` отсортирован.
Если перед проходом участки длины `width` отсортированы, обычное слияние
превращает каждую соседнюю пару в отсортированный участок длины до `2 * width`.
Остаток в конце массива тоже переносится в результат.
Значит, после удвоения `width` условие остаётся верным.
Когда `width >= n`, весь массив образует один отсортированный участок.

При равенстве берётся элемент из левого участка (`<=`), поэтому mergesort
сохраняет порядок элементов с одинаковым ключом и является стабильным.

## Итеративный quicksort

Разделение `partition(low, high)` осталось таким же, как в рекурсивной версии:
последний элемент участка выбирается опорным, после перестановок слева от него
находятся элементы `<= pivot`, справа — элементы `> pivot`.
Функция возвращает окончательный индекс опорного элемента.

Рекурсивные вызовы заменены явным стеком `stack`.
Он хранит пары индексов участков, которые ещё нужно обработать.
Обе границы, `low` и `high`, включаются в участок.

```python
stack.append((low, high))  # Отложить участок.
low, high = stack.pop()    # Взять последний отложенный участок.
```

Пока стек не пуст:

1. Достаём границы очередного участка.
2. Выполняем `partition`.
3. Добавляем в стек правый и левый участки без самого pivot.

Пустые участки и участки из одного элемента уже готовы, поэтому в стек
попадают только диапазоны, содержащие хотя бы два элемента.
Правый участок кладётся первым, левый — вторым. Стек работает по принципу LIFO,
поэтому левый участок будет обработан раньше. Для корректности порядок не важен.

### Почему вложенная функция не означает рекурсию

`partition` объявлена внутри `quicksort`, чтобы иметь доступ к `arr`.
Она не вызывает ни себя, ни `quicksort`. Само расположение одной функции
внутри другой не создаёт рекурсивных вызовов.

### Визуализация стека

Рассмотрим тот же массив. Вершина стека находится справа.

```text
arr   = [9, 3, 7, 1, 8, 2, 6]
stack = [(0, 6)]

Берём (0, 6), pivot = 6:
arr   = [3, 1, 2]  6  [8, 7, 9]
                    ↑
              pivot_index = 3

Кладём правый (4, 6), затем левый (0, 2):
stack = [(4, 6), (0, 2)]

Берём (0, 2), pivot = 2:
arr   = [1, 2, 3, 6, 8, 7, 9]
stack = [(4, 6)]

Новые участки содержат по одному элементу → не добавляем.

Берём (4, 6), pivot = 9:
arr   = [1, 2, 3, 6, 8, 7, 9]
stack = [(4, 5)]

Берём (4, 5), pivot = 7:
arr   = [1, 2, 3, 6, 7, 8, 9]
stack = []

Стек пуст → сортировка закончена.
```

### Почему алгоритм корректен

Разделение ставит pivot на окончательное место внутри обрабатываемого участка.
После этого достаточно отсортировать левую и правую части.
Именно эти части добавляются в стек, а уже готовый pivot исключается.
Каждый новый участок короче исходного, поэтому обработка завершится.
Когда стек опустеет, необработанных участков не останется и весь массив будет
отсортирован. Обмены сохраняют исходный набор элементов.

Эта реализация quicksort нестабильна: обмены могут менять относительный порядок
элементов с одинаковым ключом.

## Сложность

Пусть `n` — количество элементов. Дополнительная память включает копию входа,
буфер или явный стек, но не сам исходный массив.

| Алгоритм | Лучшее время | Среднее время | Худшее время | Дополнительная память |
|---|---|---|---|---|
| Mergesort | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` |
| Quicksort | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(n)` |

Средняя оценка quicksort предполагает случайный порядок различных элементов.

**Mergesort:** ширина участка удваивается, поэтому проходов `O(log n)`.
За каждый проход все `n` элементов записываются в буфер ровно один раз.
Копия входа и буфер занимают `O(n)` памяти; рекурсивного стека нет.

**Quicksort:** время определяется теми же разделениями, что и в рекурсивной
версии. При сбалансированных разделениях получается `O(n log n)`, при крайне
неравномерных — `O(n²)`. Копия входа занимает `O(n)`. Явный стек занимает
в среднем `O(log n)`, в худшем случае — `O(n)`, поскольку порядок обработки
участков здесь не выбирается по их размеру. `partition` использует `O(1)` памяти.

Отказ от рекурсии устраняет ограничение глубины вызовов Python, но не исправляет
плохой выбор pivot. На возрастающем, убывающем массиве и одинаковых значениях
эта версия quicksort по-прежнему выполняет `O(n²)` работы.

В частности, на возрастающем массиве явный стек содержит не больше одного
участка, однако время остаётся квадратичным. Большая глубина рекурсивной версии
и размер явного стека этой версии не обязаны совпадать: стек хранит только
ожидающие обработки участки.

## Тесты

`test_sorts()` содержит 11 явно заданных массивов:

- пустой массив и один элемент;
- два элемента в обратном порядке;
- возрастающий и убывающий порядок;
- одинаковые значения;
- отрицательные числа, ноль и повторы;
- смешанный массив длины `8`;
- массивы длины `7` и `9`, чтобы проверить неполные участки при слиянии;
- чередующиеся повторяющиеся значения.

Дополнительно проверяются:

- 100 воспроизводимых случайных массивов длины от `0` до `99`;
- возрастающий массив из `1500` элементов;
- убывающий массив из `1500` элементов;
- массив из `1500` одинаковых значений.

Последние три входа проверяют работу quicksort на случаях, в которых
рекурсивная реализация потребовала бы линейной глубины вызовов.
Настройки лимита рекурсии не изменяются.

Всего — **114 массивов для каждой сортировки**.
Для каждого проверяются результат, сохранение входа и создание отдельного списка:

```python
original = nums.copy()
result = func(nums)

assert result == sorted(nums)
assert nums == original
assert result is not nums
```

`sorted()` используется только как эталон в тестах.

Начало вывода при запуске:

```text
Проверки пройдены: 114 массивов для каждого алгоритма.
Исходный массив: [9, 3, 7, 1, 8, 2, 6]
Mergesort: [1, 2, 3, 6, 7, 8, 9]
Quicksort: [1, 2, 3, 6, 7, 8, 9]
```

## Сравнение времени

После тестов и примера вызывается `compare()`. Для обеих сортировок используются
одни и те же четыре массива длины `600`:

| Массив | Зачем нужен |
|---|---|
| Случайные различные значения | Обычный случай для quicksort |
| По возрастанию | Последний элемент всегда максимальный, разделения неравномерные |
| По убыванию | Опорный элемент последовательно оказывается крайним |
| Одинаковые элементы | Условие `<= pivot` отправляет все остальные элементы влево |

Данные воспроизводимы: используется `random.Random(42)`. Размер и способ
генерации совпадают с задачей Compare. Здесь измеряются две итеративные
сортировки между собой.

Время измеряется через `perf_counter()` вокруг вызова каждой сортировки:

```python
start = perf_counter()
result = func(nums)
elapsed = perf_counter() - start
```

В измерение входит копирование входа внутри функции. Подготовка данных,
вычисление эталона, проверки результата и печать выполняются вне измеряемого
интервала. После каждого вызова проверяется правильность результата и сохранение
исходного массива. Функции сортировки не печатают время сами: измерение находится
только в `compare()`, поэтому тесты и обычные вызовы остаются без лишнего вывода.

Пример фактического запуска 18 ноября 2026 года:

| Массив, `n = 600` | Mergesort, с | Quicksort, с |
|---|---:|---:|
| Случайный | 0.000450 | 0.000433 |
| По возрастанию | 0.000346 | 0.010293 |
| По убыванию | 0.000276 | 0.006809 |
| Одинаковые элементы | 0.000229 | 0.007713 |

В этом запуске на возрастающем массиве quicksort примерно в 30 раз медленнее
mergesort. Итеративная реализация устраняет ограничение глубины рекурсии,
но не квадратичное время при неудачных разделениях.

Каждая функция измеряется один раз на каждом массиве. Короткие измерения
зависят от окружения и нагрузки; для точного сравнения нужны повторения
и, например, медиана. Разница на случайном массиве здесь слишком мала,
чтобы по одному запуску объявлять один алгоритм быстрее другого.
