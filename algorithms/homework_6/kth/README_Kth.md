# K-th — k-й наибольший элемент массива

## Условие

Найти k-й по величине элемент массива. Полностью сортировать массив нельзя.
Кучи не используются. Решение — алгоритм quickselect.

```text
nums = [3, 2, 1, 5, 6, 4], k = 2
Ответ: 5

nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4
Ответ: 4
```

`k` считается с единицы: `k = 1` означает максимум.
Повторы занимают отдельные позиции. Например, для `[6, 5, 5, 4]` второй
и третий наибольшие элементы равны `5`.

Код и тесты находятся в [Kth.py](Kth.py).
Функция `kth_largest(nums, k)` возвращает одно значение и сохраняет исходный список.

Запускать нужно без `-O`, чтобы Python выполнял проверки `assert`.

## Идея: quicksort, но только в нужную сторону

В [итеративном quicksort](README_Iterative.md) после `partition` обрабатывались
обе части массива. Для поиска одного элемента обе части не нужны.
Достаточно продолжить только в той части, где находится искомая позиция.

`partition(low, high)` выбирает последний элемент участка опорным и выполняет
обмены так, чтобы получилось:

```text
[элементы <= pivot]  pivot  [элементы > pivot]
```

Функция возвращает индекс pivot. Внутри выбранного участка опорный элемент
уже стоит на допустимом окончательном месте, хотя соседние части ещё не
отсортированы. Одинаковые значения могут стоять слева от pivot — это допустимо.

## Почему target = n - k

Разделение устроено по возрастанию, а задача просит k-й элемент по убыванию.
Переведём номер в индекс, который этот элемент занял бы при сортировке
по возрастанию:

```text
target = n - k
```

Например, для шести элементов:

```text
Значения по возрастанию: 1  2  3  4  5  6
Индекс:                 0  1  2  3  4  5
Место по убыванию:      6  5  4  3  2  1

k = 2 → target = 6 - 2 = 4 → значение 5
```

Этот порядок нарисован только для объяснения индекса. В самом алгоритме
сортировка не выполняется.

## Пошаговый алгоритм

1. Проверяем, что `k` имеет тип `int` и лежит в диапазоне от `1` до `len(nums)`.
2. Копируем вход в `arr`, чтобы не менять исходный список.
3. Вычисляем `target = len(arr) - k`.
4. Разделяем текущий участок и получаем `pivot_index`.
5. Выбираем действие:

| Условие | Что означает | Действие |
|---|---|---|
| `pivot_index == target` | Опорный элемент — искомый | Вернуть `arr[pivot_index]` |
| `pivot_index < target` | Искомая позиция правее | `low = pivot_index + 1` |
| `pivot_index > target` | Искомая позиция левее | `high = pivot_index - 1` |

`target` — абсолютный индекс в общей копии массива. Мы меняем только границы,
не создаём срезы, поэтому пересчитывать `target` после разделений не нужно.

Когда `low == high`, остаётся один элемент. Он и является ответом.
Рекурсия и стек ожидающих участков не нужны: на каждом шаге остаётся только
один участок для дальнейшего поиска.

## Как работает partition

Границы `low` и `high` включаются в участок.

```python
pivot = arr[high]
i = low
```

`j` перебирает элементы до pivot. `i` указывает место для следующего элемента,
который не больше pivot. Перед каждой итерацией поддерживается условие:

```text
[low ... i - 1]  [i ... j - 1]  [j ... high - 1]  [high]
    <= pivot        > pivot       не проверены      pivot
```

Если `arr[j] <= pivot`, меняем `arr[i]` и `arr[j]` местами и увеличиваем `i`.
После цикла меняем `arr[i]` и опорный элемент местами. Возвращаем `i`.
Используется то же разделение Lomuto, что и в предыдущих задачах.

## Визуализация первого примера

```text
nums = [3, 2, 1, 5, 6, 4], k = 2
target = 6 - 2 = 4

Индексы:  0  1  2  3  4  5
arr:     [3, 2, 1, 5, 6, 4]
                         ↑
                      pivot = 4

Первое разделение, low = 0, high = 5:

          [3, 2, 1]  4  [6, 5]
                    ↑
              pivot_index = 3

3 < target → продолжаем только справа: low = 4, high = 5.

Второе разделение, pivot = 5:

          [3, 2, 1, 4]  5  [6]
                       ↑
                 pivot_index = 4

pivot_index == target → ответ 5.
```

Обрати внимание: `[3, 2, 1]` так и осталось неотсортированным.
Для нахождения ответа сортировать эту часть не понадобилось.

## Пример с переходом вправо и затем влево

```text
nums = [7, 2, 9, 4, 3, 8, 5, 1, 6], k = 3
target = 9 - 3 = 6

low = 0, high = 8, pivot = 6:
arr = [2, 4, 3, 5, 1]  6  [7, 9, 8]
                       ↑
                 pivot_index = 5

5 < 6 → вправо: low = 6, high = 8.

pivot = 8:
arr = [2, 4, 3, 5, 1, 6, 7, 8, 9]
                             ↑
                       pivot_index = 7

7 > 6 → влево: low = 6, high = 6.

Остался один элемент: arr[6] = 7 → ответ 7.
```

## Почему алгоритм корректен

Изначально искомая позиция находится в полном массиве.
После `partition` все элементы слева от pivot не больше него,
все справа — больше. Поэтому pivot занимает допустимую позицию в порядке
возрастания, а искомый элемент можно определить по сравнению индексов.

Если индексы совпали, ответ найден. Если `target` левее или правее, достаточно
оставить соответствующую часть. Отброшенные части больше не меняются и не
содержат искомую позицию. Этот принцип сохраняется при каждом следующем
разделении, включая случаи с повторами.

Границы сдвигаются за pivot, поэтому выбранный участок строго уменьшается.
Алгоритм обязательно найдёт ответ или дойдёт до одного оставшегося элемента.

## Сложность

Пусть `n` — длина массива.

| Показатель | Оценка |
|---|---|
| Лучшее время | `O(n)` |
| Среднее время при случайном порядке различных элементов | `O(n)` |
| Худшее время | `O(n²)` |
| Дополнительная память этой реализации | `O(n)` |

Первое разделение просматривает массив длины `n`. При удачных разделениях
дальше обрабатывается только одна из частей, и объём работы выглядит так:

```text
n + n/2 + n/4 + ... < 2n → O(n)
```

Это иллюстрация линейной работы при сбалансированных разделениях. В среднем
для случайного порядка различных элементов время тоже линейное.
У quicksort обрабатываются обе части, поэтому средняя оценка там `O(n log n)`.

В худшем случае каждый раз отбрасывается только один элемент:

```text
n + (n - 1) + (n - 2) + ... → O(n²)
```

Например, для возрастающего массива и `k = n` последний элемент каждый раз
максимальный, а искать нужно минимум. Массив из одинаковых элементов также
может приводить к квадратичному времени: `<= pivot` помещает все остальные
элементы слева. Худшее время зависит и от входа, и от искомого `k`.

Функция создаёт копию входа, поэтому использует `O(n)` дополнительной памяти.
Сам поиск в этой копии требует `O(1)` памяти: несколько индексов и переменных,
без рекурсивного стека. Результат — одно значение, то есть `O(1)` памяти.

## Тесты

`test_kth_largest()` проверяет:

- оба примера из условия;
- массив из одного элемента;
- максимум при `k = 1` и минимум при `k = n`;
- возрастающий и убывающий порядок;
- одинаковые элементы и повторяющиеся максимумы;
- отрицательные числа и ответ `0`;
- поиск с переходами в обе стороны;
- все допустимые `k` для 50 случайных массивов длины от `1` до `50`;
- `k = 1`, `k = 750` и `k = 1500` на трёх массивах длины `1500`:
  возрастающем, убывающем и состоящем из одинаковых значений;
- сохранение исходного массива после каждого вызова.

Случайные данные воспроизводимы благодаря `random.Random(42)`.
В тестах эталон получается через `sorted(nums, reverse=True)[k - 1]`.
Внутри `kth_largest` сортировка не используется.

Всего: 12 явных случаев, `1 + 2 + ... + 50 = 1275` случайных пар «массив, k»
и 9 проверок длинных массивов — **1296 корректных случаев**.

Дополнительно проверяются 7 некорректных входов:

- пустой массив, нулевой, отрицательный или слишком большой `k` → `ValueError`;
- дробный, строковый или логический `k` → `TypeError`.

Проверка `type(k) is not int` намеренно отвергает `True` и `False`, хотя
в Python `bool` является подклассом `int`. Ошибки обнаруживаются до копирования
и перестановок элементов.

Ожидаемый вывод:

```text
Проверки пройдены: 1296 корректных случаев и 7 некорректных входов.
5
4
```
