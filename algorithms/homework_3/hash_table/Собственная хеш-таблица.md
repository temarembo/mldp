## Идея решения

Хеш-таблица хранит пары:

```text
ключ -> значение
```

Например:

```text
"name" -> "Alice"
"age"  -> 25
"id"   -> 100
```

Основная идея заключается в том, что по ключу вычисляется число — **хеш**:

```python
hash(key)
```

После этого определяется индекс в массиве:

```python
hash(key) % capacity
```

Например, если размер таблицы равен `8`:

```text
hash(key) = 123

123 % 8 = 3
```

значит элемент должен находиться в бакете:

```text
buckets[3]
```

---

## Как хранятся данные

Для хранения используется только `list`.

Главный список выглядит примерно так:

```text
buckets
  |
  +-- 0 -> []
  |
  +-- 1 -> [["cat", 10]]
  |
  +-- 2 -> []
  |
  +-- 3 -> [["name", "Alice"], ["age", 25]]
  |
  +-- 4 -> []
```

Каждый элемент `buckets` — отдельный список.

Пара ключ–значение также представлена списком:

```python
[key, value]
```

Таким образом, для хранения структуры не используются `dict` или `set`.

---

## Коллизии

Коллизия возникает, когда разные ключи получают один индекс.

Например:

```text
hash(key1) % 8 = 3
hash(key2) % 8 = 3
```

Оба элемента должны попасть в:

```python
buckets[3]
```

Для разрешения коллизий используется **метод цепочек**.

В одном бакете просто хранится несколько элементов:

```python
[
    [key1, value1],
    [key2, value2],
    [key3, value3]
]
```

При поиске сначала вычисляется нужный бакет, а затем выполняется небольшой линейный поиск внутри него.

---

## Вставка

Метод:

```python
put(key, value)
```

сначала вычисляет индекс бакета:

```python
index = hash(key) % capacity
```

Затем проверяется, существует ли уже такой ключ.

Если существует:

```text
["age", 20]
```

и выполняется:

```python
put("age", 25)
```

новый элемент не создаётся, а значение обновляется:

```text
["age", 25]
```

Если ключа ещё нет, новая пара добавляется в соответствующий бакет.

---

## Поиск

Метод:

```python
get(key)
```

вычисляет бакет, в котором должен находиться ключ.

Затем элементы этого бакета последовательно проверяются.

Если ключ найден — возвращается значение.

Если такого ключа нет:

```python
raise KeyError(key)
```

Использование `KeyError` позволяет отличить отсутствующий ключ от ключа, значение которого действительно равно `None`.

Например:

```python
table.put("x", None)
```

Это корректно хранимое значение.

---

## Удаление

Метод:

```python
delete(key)
```

также сначала находит нужный бакет.

После этого внутри него ищется нужная пара и удаляется:

```python
bucket.pop(i)
```

Метод возвращает удалённое значение.

Если ключ отсутствует, выбрасывается:

```python
KeyError
```

---

## Что происходит при заполнении таблицы

Если таблица становится слишком заполненной, количество коллизий начинает увеличиваться.

Для контроля используется **коэффициент заполнения**:

```text
load factor = количество элементов / количество бакетов
```

В реализации используется граница:

```text
0.75
```

То есть перед добавлением нового элемента проверяется:

```python
(self.size + 1) / self.capacity > 0.75
```

Если таблица заполнена более чем на 75%, её размер увеличивается в два раза.

Например:

```text
capacity = 8
```

становится:

```text
capacity = 16
```

---

## Почему при изменении размера нужно перестраивать таблицу

Нельзя просто скопировать старые бакеты в новую таблицу.

Индекс зависит от `capacity`:

```python
hash(key) % capacity
```

Например:

```text
123 % 8  = 3
123 % 16 = 11
```

После изменения размера тот же ключ может попасть уже в другой бакет.

Поэтому `_resize()` заново вставляет каждый элемент в новую таблицу.

Этот процесс называется **rehashing**.

---

## Визуализация

Пусть создана маленькая таблица:

```python
table = HashTable(4)
```

Изначально:

```text
0 -> []
1 -> []
2 -> []
3 -> []
```

Добавляем:

```python
table.put(1, "A")
```

Так как:

```text
1 % 4 = 1
```

получаем:

```text
0 -> []
1 -> [[1, "A"]]
2 -> []
3 -> []
```

Теперь:

```python
table.put(5, "B")
```

Для целых чисел:

```text
5 % 4 = 1
```

Получилась коллизия.

Метод цепочек сохраняет оба элемента:

```text
0 -> []
1 -> [[1, "A"], [5, "B"]]
2 -> []
3 -> []
```

Теперь поиск:

```python
table.get(5)
```

сначала вычисляет:

```text
5 % 4 = 1
```

и просматривает только:

```text
[[1, "A"], [5, "B"]]
```

После нахождения ключа `5` возвращается:

```text
"B"
```

---

## Оценка сложности

Пусть `n` — количество элементов в таблице.

При хорошем распределении хешей бакеты содержат небольшое количество элементов.

Поэтому в среднем:

```text
put    — O(1)
get    — O(1)
delete — O(1)
```

В худшем случае все ключи могут попасть в один бакет:

```text
bucket = [
    [key1, value1],
    [key2, value2],
    ...
    [keyN, valueN]
]
```

Тогда операции превращаются в линейный поиск:

```text
O(n)
```

Изменение размера таблицы требует перераспределить все элементы:

```text
O(n)
```

Но resize происходит не после каждой вставки, поэтому **амортизированная** сложность вставки остаётся:

```text
O(1)
```

Память:

```text
O(n)
```

## Тесты

```python
# Базовая вставка и поиск
table = HashTable()

table.put("name", "Alice")
table.put("age", 25)

assert table.get("name") == "Alice"
assert table.get("age") == 25
assert len(table) == 2


# Обновление существующего ключа
table = HashTable()

table.put("age", 20)
table.put("age", 30)

assert table.get("age") == 30
assert len(table) == 1


# Удаление элемента
table = HashTable()

table.put("a", 10)
table.put("b", 20)

assert table.delete("a") == 10
assert len(table) == 1
assert table.contains("a") is False
assert table.contains("b") is True


# Коллизия
# Для capacity = 4 числа 1 и 5 попадают в один бакет
table = HashTable(4)

table.put(1, "one")
table.put(5, "five")

assert table.get(1) == "one"
assert table.get(5) == "five"
assert len(table) == 2


# Удаление одного элемента при коллизии
table.delete(1)

assert table.get(5) == "five"
assert table.contains(1) is False


# Хранение None
table = HashTable()

table.put("empty", None)

assert table.get("empty") is None
assert table.contains("empty") is True


# Отрицательные и нулевые ключи
table = HashTable()

table.put(0, "zero")
table.put(-10, "negative")

assert table.get(0) == "zero"
assert table.get(-10) == "negative"


# Проверка автоматического resize
table = HashTable(4)

old_capacity = table.capacity

for i in range(10):
    table.put(i, i * 10)

assert table.capacity > old_capacity
assert len(table) == 10

for i in range(10):
    assert table.get(i) == i * 10


# Проверяем, что после resize ничего не потерялось
assert table.get(0) == 0
assert table.get(5) == 50
assert table.get(9) == 90


# Отсутствующий ключ
table = HashTable()

try:
    table.get("missing")
    assert False
except KeyError:
    pass


# Удаление отсутствующего ключа
try:
    table.delete("missing")
    assert False
except KeyError:
    pass
```

### Что проверяют тесты

Тесты покрывают:

- обычную вставку;
- поиск;
- обновление уже существующего ключа;
- удаление;
- проверку существования ключа;
- коллизии;
- удаление одного элемента из цепочки коллизий;
- хранение значения `None`;
- целые отрицательные и нулевые ключи;
- автоматическое увеличение таблицы;
- сохранность элементов после `rehashing`;
- поиск отсутствующего ключа;
- удаление отсутствующего ключа.
