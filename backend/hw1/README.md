# API модерации объявлений

Учебный HTTP-сервис на Python и FastAPI. Принимает данные объявления,
проверяет возможность публикации по простому правилу и сохраняет последний
результат проверки в памяти.

## Установка

Проект проверен на Python 3.14.4. Команды ниже предназначены для macOS и Linux.

```bash
git clone https://github.com/temarembo/mldp.git
cd mldp/backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r hw1/requirements.txt
cd hw1
```

Все Python-зависимости, включая зависимости для запуска и тестирования,
перечислены в `requirements.txt`.

## Запуск

Из папки `backend/hw1` с активированным виртуальным окружением:

```bash
fastapi dev
```

Эквивалентный запуск через Python-модуль — `python -m fastapi dev`.

Сервис доступен по адресу <http://127.0.0.1:8000>.
Интерактивная документация для отправки запросов — <http://127.0.0.1:8000/docs>.
Остановка сервера — `Ctrl+C`.

## POST /predict

Обработчик принимает JSON-объект. Все поля обязательны:

| Поле | Тип | Описание |
| --- | --- | --- |
| `seller_id` | integer | Идентификатор продавца |
| `is_verified_seller` | boolean | Признак подтверждённого продавца |
| `item_id` | integer | Идентификатор объявления |
| `name` | string | Название объявления |
| `description` | string | Описание объявления |
| `category` | integer | Идентификатор категории |
| `images_qty` | integer | Количество фотографий, не меньше нуля |

Проверка типов строгая: строка `"1"` не принимается вместо числа `1`,
а строка `"true"` — вместо булева значения `true`.
Значение `images_qty` должно быть неотрицательным: отрицательное количество
фотографий отклоняется со статусом `400` независимо от подтверждения продавца.
Для остальных полей ограничения на диапазоны чисел и длину строк не установлены.

### Правило модерации

- Подтверждённому продавцу публикация разрешена независимо от количества фотографий.
- Неподтверждённому продавцу публикация разрешена, если `images_qty > 0`.
- В остальных случаях публикация отклоняется.

В решении участвуют только `is_verified_seller` и `images_qty`.
Текст объявления и остальные поля принимаются и проверяются по типам.

Тело успешного ответа — одно JSON-значение:

- `true` — публикация разрешена;
- `false` — публикация отклонена.

### Пример запроса

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "seller_id": 1,
    "is_verified_seller": false,
    "item_id": 10,
    "name": "Велосипед",
    "description": "Почти новый",
    "category": 2,
    "images_qty": 1
  }'
```

Ответ со статусом `200`:

```json
true
```

### Статусы ответа

| Статус | Значение |
| --- | --- |
| `200` | Проверка выполнена; ответ содержит `true` или `false` |
| `400` | Пропущено обязательное поле, нарушен тип данных, передан отрицательный `images_qty` или некорректный JSON |
| `500` | Возникла неожиданная ошибка при обработке запроса |

Отклонённое объявление возвращает `200` и `false`: сама проверка выполнена успешно.
При ошибке `400` поле `detail` содержит описание ошибок валидации.
Ответ при внутренней ошибке:

```json
{"detail": "Internal server error"}
```

## Архитектура

```text
backend/hw1/
├── main.py                         # Приложение и обработчики ошибок
├── dependencies.py                 # Создание и предоставление репозитория
├── models/prediction.py             # Модель входных данных
├── routers/prediction.py            # HTTP-обработчик
├── services/prediction.py           # Правило модерации и сохранение результата
├── repositories/prediction.py       # Хранение результатов в памяти
├── tests/                          # Тесты сервиса, API и репозитория
└── requirements.txt                # Зафиксированные версии зависимостей
```

Обработчик передаёт данные сервису. Сервис вычисляет решение, сохраняет его
через репозиторий и возвращает обработчику булев результат.

### Допущение о репозитории

В задании требуется слой репозитория, но не определено, какие данные хранить.
В этой реализации принято допущение: репозиторий хранит последний результат
модерации для каждого `item_id` в словаре `item_id → bool`.

Повторная проверка того же `item_id` заменяет предыдущее решение.
Хранилище существует только в памяти процесса: перезапуск сервера, включая
автоматическую перезагрузку в режиме разработки, очищает результаты.
У разных процессов отдельные хранилища. Отдельного HTTP-обработчика для чтения
результатов нет.

## Тесты

Из папки `backend/hw1` с активированным виртуальным окружением:

```bash
pytest -v
```

Альтернативная команда:

```bash
python -m pytest -v
```

Обе команды также работают из папки курса `backend` и запускают тесты первого ДЗ.
Настройки в `backend/pytest.ini` указывают путь `hw1` для импортов и `hw1/tests`
для поиска тестов при запуске из папки курса.

Тесты проверяют:

- решения для сочетаний подтверждения продавца и наличия фотографий;
- успешные HTTP-ответы и сохранение результата запроса;
- отсутствие обязательных полей, неправильные типы, отрицательный `images_qty`
  для подтверждённых и неподтверждённых продавцов и некорректный JSON;
- ответ `500` при искусственном сбое сервиса;
- чтение, сохранение и замену результатов в репозитории.

HTTP-тесты используют `TestClient` внутри процесса. Отдельно запускать сервер
для них не требуется. Каждый HTTP-тест получает отдельный репозиторий в памяти.
